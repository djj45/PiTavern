# PiTavern（π 酒馆）— 基于 pi 的 agent 原生酒馆实施计划

## 定位

把上个会话的结论落地：社区在提示词层手搓的运行时能力（按需召回、强制工具输出协议、历史压缩、状态投影）**下沉到真正的 agent 运行时层**。引擎用 pi（`pi-agent-core` + `pi-ai`），数据生态兼容 SillyTavern（人物卡/世界书/预设/聊天记录直接读写），前端全新构建（agent 原生 UI）。

你已拍板的三个决策：**全新原生前端** · **双模式上下文（桥接先行）** · **MVP 含工具四件套+输出协议+历史压缩+可视化面板**。

## 关键设计（均已在源码/快照中验证）

1. **引擎**：pi `Agent` 类（`packages/agent/src/agent.ts:194`）。无内建轮次上限 → 用 `finishTurn` 返回 `{action:"end"}` 实现"单回合回复"；工具并发用默认 parallel；`transformContext` 是历史压缩的挂载点。
2. **中转接入**：`createProvider({id, baseUrl, auth, models, api: openAICompletionsApi()})`（pi-ai README:1274 起，官方支持代理/本地端点）；`compat` 字段处理中转协议怪癖。同时保留 OpenAI/Claude/Gemini 等内置 provider。限制：模型须支持 function calling（输出协议本就依赖工具，文档标注即可）。
3. **桥接组装器**：复刻 ST Chat Completion 组装语义——`prompts[] + prompt_order[]` 顺序开关引擎、宏核心集（`{{char}}/{{user}}/{{random}}/{{roll}}/{{getvar}}/时间`，参考 `public/scripts/macros/`）、世界书关键词扫描（scan depth/递归/selective logic/sticky/cooldown，参考 `world-info.js`）、injection_position/depth。只做 Chat Completion 系，不做 text-completion/instruct。验收集：**猫神预设 + ST Default 预设**对齐输出。
4. **工具四件套**（参数规格照抄 `/Users/djj45/Downloads/request-context.json`）：
   - `worldbook_search(query/read/refs/limit/offset)` — 查询命中→refs 读全文两级检索；
   - `tavern_recall_history(query|turn, radius, limit)` — **限次冷却改为运行时强制**（每轮≤6 次、完整正文召回后冷却 10 轮用计数器实现，不再靠提示词自觉）；
   - `tavern_read_variables(list/search/read, path, cursor)` — 分页只读；
   - `tavern_read_skill_reference(name, path)`。
   检索实现：本地 BM25/关键词索引（不引向量库，留扩展位）。
5. **输出协议**：原生 function calling 取代猫神伪 JSON+预填——`game_content`（正文，必选）+ `tavern_think`（思维链容器，可选）双工具，MUST 调用约束写进 description；服务端 consumeToolCalls 还原为消息流，思维链进折叠 UI。流式期间直接渲染工具参数增量（天然防截断可视）。
6. **历史压缩**：`transformContext` 内实现——近 N 轮全文，早期轮 squash 为 `|用户|/|游戏剧情|` 折叠块（分隔符沿用猫神 `<|sep|>` 语义）+ `<summary>` 渐进摘要（摘要可配独立便宜模型/手动触发）；压缩只影响送上游的上下文，UI 永远显示全量原文。
7. **事件协议**：WS JSONL 事件流（借鉴 pi coding-agent rpc 模式）：`message_delta / tool_start / tool_end / recall_hit / state_projection / usage / compressed / error`。
8. **前端**：Vite + React + TS + Tailwind（无既有偏好约束，选生态最全的栈；聊天流+右侧面板+顶部模式开关）。

## 里程碑

- **M1 行走骨架**：workspace 脚手架；server 起 HTTP+WS、pi Agent 接中转跑通单会话流式；web 基础聊天 UI（发送/流式/会话切换）；ST 数据加载（人物卡解析+聊天 JSONL 读写）。
- **M2 桥接组装器**：预设加载 + prompt_order 引擎 + 宏 + 世界书扫描注入；用猫神预设与 ST 实际请求对齐验证。
- **M3 工具四件套 + 可视化**：四工具 + 限次冷却运行时强制；UI 工具卡片、召回命中面板、token/成本统计。
- **M4 输出协议 + 历史压缩**：game_content 模式 + 还原；squash + summary 折叠；思维链折叠 UI。
- **M5 接管模式**：人物卡→system sections、常驻世界书→system、非常驻→工具检索、每轮状态投影；模式开关上线。
- **M6 打磨**：导入导出、皮肤、移动端适配；多角色群聊（后置评估）。

## 风险与对策

- ST 组装语义复刻不全（宏长尾、instruct 模板）→ 桥接模式标 beta，以两款真实预设 为验收基线，缺口记文档。
- pi 锁 1.4.0、API 演进快 → 锁版本 + `agent/engine.ts` 单点适配层。
- 中转协议差异 → pi-ai `compat` 配置 + 连接测试按钮（发 1 token 探活）。
- pi-ai 仅收支持 function calling 的模型 → 与输出协议要求一致，文档标注；桥接模式下纯补全模型不可用。
