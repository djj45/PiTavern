# PiTavern（π 酒馆）

当前版本：**0.2.1**。新安装、升级和回退见 [发布说明](docs/RELEASE.md)，兼容边界见 [兼容说明](docs/COMPATIBILITY.md)。

基于 [pi](https://github.com/earendil-works/pi) agent 运行时的 agent 化酒馆。数据生态兼容 [SillyTavern](https://github.com/SillyTavern/SillyTavern)（角色卡 / 世界书 / 预设 / JSONL 聊天记录）。

## 一键启动

macOS 双击项目根目录的 **`start.command`** 即可，也可以在终端执行 `npm start`。

需先安装 Node.js 22.19 或更高版本（含 npm）。脚本自动安装缺失依赖、构建前端、启动服务并打开浏览器；首次安装依赖需要联网。前后端共用一个地址，无需另外启动 Vite。

默认地址为 `http://127.0.0.1:8787`，已有配置中的端口会自动生效。保持启动窗口打开；按 `Ctrl+C` 或关闭窗口可停止本次服务。端口被占用时会显示提示，可在终端改用其他端口：

```sh
PORT=9898 ./start.command
PITAVERN_OPEN_BROWSER=0 ./start.command # 不自动打开浏览器
```

`PITAVERN_CONFIG` 可指定其他配置文件；相对路径以项目根目录为基准。启动失败时，双击打开的窗口会保留错误信息，按回车后退出。

## 开发

```sh
npm install
npm run dev:server   # 服务端 http://127.0.0.1:8787（tsx watch）
npm run dev:web      # 前端 http://localhost:5173（vite，代理 /api /ws）
npm run check        # 全仓类型检查
npm run e2e          # mock 中转端到端冒烟（含工具循环）
npm run verify:bridge # 桥接组装器对齐验证（真实猫神预设）
npm run verify:tools # 工具四件套 + 限次冷却强制验证
npm run verify:m4    # 输出协议还原 + 流式提取 + 历史压缩验证
npm run verify:takeover # 接管模式组装 + 状态投影验证（合成数据，无需本地角色卡）
npm run verify:m6    # 世界书计时效果（sticky/cooldown/delay）验证
npm run verify:regression # 空聊天/缓存/完整工具轮压缩/前端会话状态回归
npm run verify:chat-ux # 世界书边界/生成事务/候选切换/备份恢复/历史分页与双窗口同步
npm run verify:branches # 多分支树：任意回合切换、后续剧情保留、状态恢复、自动候选与换路线指令
npm run verify:rendering # Markdown 表格/折叠/代码/安全过滤
npm run verify:compat # 变量持久化/向量索引/最少激活数/instruct/文本补全（本地模拟接口）
npm run verify:models # 模型列表、草稿连接、密钥复用、超时与取消、单模型思考等级（本地模拟接口）
npm run verify:greetings # 备用开场白、翻页落库、原版 swipes、版本冲突与实际请求
npm run verify:library # 世界书/正则编辑、PNG 保留、全局执行顺序、整库备份迁移
npm run verify:regex-isolation # 提示词正则隔离、超时与取消回滚
npm run verify:library-maintenance # 便携设置、任务进度、取消和归档管理
npm run verify:ci     # 17 组独立合成数据回归，不需要本机资料库或真实 API Key
npx playwright install chromium # 首次运行浏览器验收时安装 Chromium
npm run build && npm run verify:browser # 33 项真实界面验收，独立合成库与本地 mock
```

聊天切换和断线重连通过 WebSocket 快照恢复历史与生成进度。设置变更从下一回合生效，当前生成仍可停止。聊天读取按文件修改时间缓存，兼容外部修改的 ST 记录。

接管模式的状态投影通过增量事件更新。工具活动和模型回传用量按生成独立保存，重新生成、刷新或重启后仍可查看。角色卡、常驻世界书与历史中的宏在组装时展开；开场白随首轮保留，直到首轮离开历史窗口。全局世界书可直接在各上下文模式下导入和启用。

三种上下文模式统一在 Agent 层压缩完整旧轮次，保留当前工具调用链，并为输出预留预算。已知模型使用 `cl100k_base` / `o200k_base` tokenizer；未知模型明确回退到字符和 UTF-8 字节估算。设置中选中模型后，可填写实际上下文长度、最大输出和计数方式，中转模型别名可手动指定编码器。聊天封装和工具协议开销仍是估算，不能替代供应商账单。文本补全计数包含完整 instruct 模板。输入预算扣除输出上限和剩余空间的 10% 余量；即使关闭压缩，超预算请求也会在发送前终止。

### 生成记录与上下文诊断

右上角「统计」→「生成记录与上下文诊断」，可分页查看每次发送、重新生成或重试的结果、已回传 token 用量和工具活动。对话轮次按当前聊天中的用户消息统计；生成次数包含成功、失败、取消和服务中断的尝试。未回传的用量无法补算，导入聊天及功能启用前的历史也不会伪造统计。模型分多次调用时累计所有已收到的用量，切换候选或恢复备份不会回滚已发生的消耗。

诊断展示本次生成最近一次请求的计数方式、输出预留、输入预算、压缩前后 token、压缩轮数和消息数，以及系统提示、对话/工具结果、工具声明和封装的占用。世界书组装记录列出注入、预算过滤、未命中、禁用、概率、计时条件和缺少预设插入位置等原因；每次保留前 200 条诊断，筛选不会重新执行宏或扫描。接管模式还显示历史窗口省略的消息数。

记录独立保存在 `<stDataDir>/.pitavern/activity/<聊天 ID 的 sha256>/`，按每次生成原子更新；服务重启会将未结束记录标为中断，并保留此前收到的工具结果和用量。JSONL/MD 聊天导出不包含这些记录，完整迁移可使用「资料库 → 备份与迁移」。验证：`npm run verify:activity`、`npm run verify:chat-ux`。

`npm run e2e` 使用独立测试目录和动态端口，测试数据与逐次 mock 请求记录保留在 `data/test-runs/`，不依赖真实 API Key。

首次使用：打开前端 → 设置 → 添加中转（OpenAI 兼容 baseUrl + API Key）→ 获取模型列表并选择添加，或手动填模型 ID → 测试连通 → 把角色卡 PNG 放进 `data/st/characters/` → 开始新对话。

「获取模型列表」使用当前表单中的地址和密钥，访问接口前缀下的 `GET /models`，例如 baseUrl 为 `https://example.com/v1` 时访问 `/v1/models`。无需先保存连接，留空密钥可复用该连接已保存的密钥；若更改地址，需重新填写密钥。支持搜索 ID／名称、去重和逐项添加；获取与取消不会改动默认模型、已有模型参数或配置文件，添加后自动保存。服务返回空列表、不支持接口或请求失败时仍可手动添加。列表可能包含 embedding 等非聊天模型，也不会自动提供上下文长度或输出上限，需按模型实际能力核对。超时为 15 秒，支持取消；编辑地址或密钥会清除列表并取消旧请求。

角色卡带有 `alternate_greetings` 时，新建聊天后点击输入框底部「🎭 开场白」按钮（位于「分支」左侧）打开开局列表，选择后正文随之更新。该按钮只在首条用户消息发出前显示，之后不再提供开局切换。默认介绍页里的编号目录会用作对应开局的标题；没有目录时显示正文摘要。只有选中的一页进入后续对话，其他开局不会一起发送。切换即时保存为 ST 原生 `swipes`／`swipe_id`，刷新和重启后保留，JSONL 导出同样保留；原角色卡和世界书不变。旧聊天尚无用户发言且只有一条开场消息时也可切换，手写开场不会被自动覆盖。首条用户消息发出后隐藏选择器，已有剧情请新建聊天选择开局；群聊不提供整组开场切换。每次切换先备份，其他窗口修改过聊天时拒绝覆盖。

`data/config.json` 存连接配置（含明文 API Key，已在 .gitignore 中）。`stDataDir` 可指向现有 SillyTavern 的 `data/default-user` 直接复用角色卡与聊天记录。

## 路线图

- **M1 行走骨架** ✅ pi Agent 引擎 + 中转接入 + WS 流式 + ST 人物卡/聊天读写 + 基础聊天 UI
- **M2 桥接组装器** ✅ ST 预设兼容组装（prompt_order 引擎 / 宏核心集 / 世界书扫描递归 / 提示词正则 / 深度注入 / 采样透传），猫神预设实测对齐（`npm run verify:bridge`）
- **M3 工具四件套** ✅ worldbook_search（片段→refs 两级检索）/ tavern_recall_history（query 片段 + turn 全文）/ tavern_read_variables（ST chat_metadata.variables 兼容）/ tavern_read_skill_reference；召回限次（每轮≤6）与冷却（全文召回后 10 轮）由**运行时强制**；UI 工具卡片流 + 用量/召回面板（`npm run verify:tools`）
- **M4 输出协议 + 历史压缩** ✅ game_tool 模式：`game_content`（正文，MANDATORY）+ `tavern_think`（思维链）双工具原生 function calling 取代伪 JSON 预填；consumeToolCalls 还原落库（mes 正文 + extra.thinking/summary）；参数流式宽松提取（toolcall_delta 实时渲染正文）；`tool_choice=required` 可透传；历史压缩 transformContext（超预算时旧轮 summary 优先折叠为 |用户|/|游戏剧情| 块，UI/落库永远全文）（`npm run verify:m4`）
- **M5 接管模式** ✅ agent 原生组装：人物卡/常驻世界书/persona 进 system named sections，关键词条目 0 注入（全靠 worldbook_search）；历史只带近 N 轮（更早靠召回）——上下文成本随需求而非历史增长；`tavern_set_state` 状态投影工具每轮结算现场快照写入 `chat_metadata.projection` 并回注 system，「统计」实时显示（`npm run verify:takeover`）
- **M6 打磨** ✅ 世界书计时效果（sticky 保活→到期自动进 cooldown 压制；delay 前置压制；状态持久化 `chat_metadata.timedWorldInfo`，单位消息数，对照 ST WorldInfoTimedEffects）；导入导出（侧栏上传角色卡 PNG/JSON、设置导入世界书、聊天导出 MD/JSONL）；主题（夜琥珀/林间绿/羊皮纸，顶栏「主题」打开面板可自由调整界面颜色）；移动端适配（抽屉导航 + 浮层面板）（`npm run verify:m6`）
- **M7 剧情分支** ✅ 重新生成保留候选并支持多分支树：可回到任意历史回合切换候选，未选中的后续剧情/状态原样保存并可恢复；设置中可开启每次成功回复后自动追加 0–4 个候选，分支面板支持「换条路线」的本次生成指令（`npm run verify:branches`）
- **新增兼容** JSON/PNG 卡内世界书编辑、CharX/BYAF 导入、2–12 人群聊、STscript 核心解释器。完整扩展生态与原版群组文件迁移仍未覆盖，详见 [兼容说明](docs/COMPATIBILITY.md)。

## 聊天操作与显示

- **编辑消息**：每条消息下方点击「编辑」，编辑框会铺满聊天区可用宽度（不再限制在消息气泡内），保存或用 Ctrl/Cmd+Enter 提交，Esc 取消。只修改当前消息，后续对话保留；相关旧摘要、状态投影、世界书计时缓存失效。原版存档中的未知字段及未选中的候选回复保留；当前候选回复会同步修改。生成中不能编辑，其他窗口先修改时会提示冲突。
- **对话列表**：鼠标悬停对话项（触屏/窄屏常显）出现「⋯」，菜单提供置顶/取消置顶、重命名、归档、删除。置顶项排在最前并显示 📌；重命名与归档/置顶保存在该聊天的 `chat_metadata`，刷新和重启后保留；归档对话从主列表隐藏，可在「已归档 (N)」区域展开、取消归档或删除。删除需要二次确认。
- **聊天操作菜单**：输入框左下角的「＋」提供 STscript、作者注释、备份与恢复、导出 MD、导出 JSONL；聊天顶部原来的角色名/消息数/操作按钮整行已移除，正文区域更大。
- **顶栏提示**：主题、统计、资料、设置四个按钮悬停或键盘聚焦时立即显示简明说明（主题与配色 / 用量与工具调用统计 / 世界书、正则脚本、备份与迁移等 / 模型连接与运行设置），不再依赖系统 title 的延迟。
- **底部模型选择**：输入框底部的模型和推理等级采用无边框文字选择（文字 + 下拉箭头，风格与 DSH 一致），点击即可切换。
- **逐模型测试**：模型表格「Token 计数」右侧新增「测试」列，点击每行的 ⚡ 会用该模型发一次最小探活请求；成功变绿、失败变红，失败原因包含在按钮的无障碍标签中。
- **推理等级**：设置 →「模型连接」的模型表格可直接给每个模型设「思考等级」（关闭/最低/低/中/高）；非关闭即视为推理模型，保存后输入框底部模型选择旁出现「推理」下拉框，切换会更新该模型的等级并持久化。中转站或关闭等级的模型不显示该控件。模型连接表单采用 CC Switch 风格：名称/接口/API Key 分区，模型列表逐行编辑显示名、请求 ID、上下文窗口、最大输出、思考等级、Token 计数。
- **生成计时**：流式回复气泡显示「思考中/生成中 + 已用时间」，开始时间由服务端记录，刷新或断线重连后从正确起点继续；回复结束、失败或停止后计时消失。
- **生成与重试**：普通发送和重新生成都在整轮成功、返回非空正文后，一次性保存助手回复、变量和计时状态。空响应、失败或停止不保存半成品，也不推进这些状态；普通发送保留用户消息，点击发送按钮左侧的 ↻ 即可重试，无需再次发送。投影工具的实时预览在失败后恢复原状态。
- **剧情分支与路线管理**：发送按钮左侧的 ↻ 重新生成最后一条回复，旧回复自动保留为候选；输入框底部「⑂ 分支」打开完整分支管理窗口。目录按故事起点/分叉回合折叠，包含当前活动路径之外、保存在 `continuation` 里的非活动子分支；支持搜索名称/剧情/路径、全部/收藏/最近访问筛选、同级分页、未继续候选折叠、定位当前和收起其他分支。点击目录节点只预览（读取原文消息，下滑分页加载全文），点「继续这条路线」才切换；跨层路线由服务端一次解析祖先路径并原子写入，失败保留原 JSONL。支持重命名和收藏（写入 `chat_metadata._pitavernBranchMeta`），切换后保留「返回刚才路线」。非活动分支的后续剧情和状态原样保存；切换时恢复变量、投影、计时和召回状态。单段候选同步写入原版 `swipes`，分支后续保存在用户消息的 `extra._pitavernReplies`，原版酒馆只看到当前活动路径。
- **自动候选与换路线**：设置 →「剧情分支与自动候选」可让每次成功回复后自动再生成 0–4 个候选（每个候选都是一次独立模型调用，会额外消耗 token/费用；生成中可停止）。「剧情分支」面板底部的「换条路线」可以输入本次生成的方向要求，只影响这一次请求，不写进聊天记录。
- **设置自动保存**：设置里的修改会在约 0.7 秒防抖后自动保存，点击「关闭设置」或遮罩也会先保存再关闭；底部不再有取消/保存。模型连接区顶部的「测试连通」会先保存再测试默认模型；模型列表每行还有 ⚡ 可单独测试该模型，成功变绿、失败变红。
- **还原设置**：底部「恢复默认配置（模型配置除外）」重置非模型设置（保留模型连接、API Key、默认模型和数据目录）；「放弃本次更改」把设置恢复到本次打开面板时的状态并关闭。
- **主题与配色**：顶栏「主题」打开「主题与配色」面板，可切换夜琥珀/林间绿/羊皮纸预设，也可自由调整背景、面板、边框、强调色、文字等颜色；改动即时生效并保存在本地。
- **聊天配色**：设置 →「聊天配色」可分别选择角色回复颜色、默认对白颜色，并为每组对白符号单独设色；默认符号对是「」和“”。两个符号之间（含符号）使用该组颜色，点「默认」跟随默认对白颜色或强调色。对白识别只发生在显示层，存档与模型上下文保持原文；思考文字不再单独设色。
- **状态恢复**：本版本生成的用户消息保存本轮开始前的变量、计时效果、状态投影及召回计数检查点，重生成从检查点执行，避免重复推进状态。旧版/外部存档没有检查点时保留现有变量，清除无从还原的投影与计时状态；无法重建原版工具副作用。编辑较早消息会使后续检查点失效，手工变量仍保留。
- **存档保护**：编辑、成功重生成、候选切换和恢复备份前，把原 JSONL 备份到数据目录下的 `.pitavern/backups/<聊天路径哈希>/`，再原子替换文件。「＋」→「备份与恢复」可按时间浏览、预览并恢复整份存档；恢复前也会备份当前内容。备份不会自动删除。生成期间发现外部文件变化、或预览后聊天又变化时，会拒绝覆盖。
- **长聊天**：打开或重连先加载最近 80 条消息，向上通过「加载更早的消息」继续分页。视口外的消息保留占位高度，附近才挂载 Markdown；正在编辑的消息保持挂载。连续正文增量按 50ms 合并，结束事件前立即刷新。分页仅影响界面传输和渲染，模型历史和 MD/JSONL 导出保持完整。
- **Markdown 显示**：支持标题、列表、引用、表格、代码块、链接和 `<details><summary>` 折叠，流式正文同样渲染。显示前会以只读方式展开 `{{user}}`、`{{char}}`、`{{getvar}}` 等宏；`{{setvar}}` 等写入宏在显示层不生效。原始消息、编辑内容和 JSONL/模型上下文保持原文。HTML 经过安全过滤，不运行角色卡脚本、内联事件或任意样式；解析器按需加载。

## 工具四件套（M3）

两种上下文模式下都可用，缺一不可的运行时能力：

| 工具 | 说明 |
|---|---|
| `worldbook_search` | 片段搜索（query）→ 全文读取（refs / read=true）两级检索；搜全部条目不限自动召回 |
| `tavern_recall_history` | query 关键词召回片段 / turn 按轮读完整正文；**每轮 ≤6 次、全文召回后冷却 10 轮，运行时强制拒绝**（不靠提示词自觉） |
| `tavern_read_variables` | 只读查询存档变量（list/search/read 分页）；数据在聊天 JSONL 首行 `chat_metadata.variables`（ST 兼容，可通过 setvar 宏写入） |
| `tavern_read_skill_reference` | 读 `data/st/skills/<名>/references/*.md`（防目录穿越） |

右上角「统计」：实时工具卡片（含拒绝/冷却态）、token 用量、召回预算状态。

## 接管模式（M5）

设置 → 对话上下文 → 「Agent 接管」。这是 dsh-tavern 模式的 pi 版——上下文经济学最优解：

| 机制 | 说明 |
|---|---|
| system sections | 人物卡 / 常驻世界书 / persona / 状态投影 / 输出协议各自成 section，每轮重建 |
| 世界书按需 | 常驻（constant）条目注入；关键词条目 0 注入，全部靠 `worldbook_search` 检索 |
| 召回制历史 | 只带最近 N 轮全文（默认 3），更早剧情靠 `tavern_recall_history`；token 随"这轮需要什么"增长 |
| 状态投影 | 模型每轮用 `tavern_set_state` 结算现场快照（人物/地点/关键物品），写入 `chat_metadata.projection` 回注下一轮 system；「统计」可见 |

## 桥接模式（M2）

设置 → 对话上下文 → 「ST 预设桥接」，选择 `OpenAI Settings/` 下的预设即可让现有 ST 预设生态生效（如猫神预设）。实现范围与已知差异：

| 能力 | 状态 |
|---|---|
| prompts + prompt_order（含 marker 与绝对深度注入） | ✅ |
| 宏核心集（char/user/random/pick/roll/getvar/时间/{{trim}}/{{// 注释}}） | ✅ |
| 世界书（常驻/关键词正则全词匹配/二级逻辑/递归/exclude/prevent/delayUntilRecursion/概率） | ✅ |
| 提示词正则（promptOnly、placement、minDepth/maxDepth） | ✅ |
| 世界书 inclusion groups / Outlet | ✅ 权重、优先级覆盖、关键词评分、多组、命名出口宏 |
| 显示层正则 | ✅ 全局、预设和角色卡脚本；用户/助手/思考文本、深度过滤、流式与历史渲染 |
| 世界书／正则编辑器 | ✅ 资料库可视化编辑、正则预览、自动备份、版本冲突保护 |
| 作者注释编辑 | ✅ 输入框左下角「＋」→「作者注释」；正文、间隔、深度、位置、角色 |
| 采样参数透传（temperature/top_p/top_k/max_tokens…） | ✅（中转默认用 max_tokens 字段） |
| system 消息位置 | ⚠️ pi 运行时把所有 system 按序合并为开头一条（内容无损，历史后指令的"尾部位置"效果不保留） |
| 向量条目 | ✅ 桥接模式：OpenAI 兼容 embeddings、内容索引缓存、相似度阈值与召回上限 |
| min activations | ✅ 扩大历史扫描范围、最大深度、token 预算（未知模型估算）；概率失败不会反复重抽 |
| instruct 模板 | ✅ 单人对话序列、story 包装、首末序列、名字宏及停止串；内置 ChatML/Alpaca，可导入 ST instruct JSON |
| text-completion 系 API | ✅ OpenAI 兼容 `/completions`（SSE 或 JSON）；其他原生协议尚未接入 |
| `{{setvar}}` 写变量 | ✅ 本轮顺序求值、嵌套宏、空字符串赋值；保存到聊天 `chat_metadata.variables` |

世界书进一步对齐：扫描深度 0 不扫描聊天正文（仍可由最少激活数扩展）；条目独立深度 0 不继承全局深度；常驻条目遵守概率开关，sticky 保活不重抽概率。支持原版卡内书 snake_case 扩展字段、数值角色和全局大小写设置继承。作者注释前后与示例对话前后分别定位。深度注入以原始历史为基准，不受其他注入条目移位影响；pi 的 system 消息合并限制仍然存在。

### 兼容功能配置

- **分组择一**：读取世界书的 `group`（逗号分隔）、`groupOverride`、`groupWeight`、`useGroupScoring`；卡内书支持对应 snake_case 扩展字段。同轮候选先保留有效 sticky，再按命中键数过滤，启用覆盖时取最高 Order，否则按权重抽取。设置 → 世界书检索可启用全局评分，条目可单独覆盖。分组后继续检查概率与预算；递归和扩大扫描不会再次占用已入选的组，诊断会记录淘汰原因。
- **Outlet**：条目设置 `position: 7` 和 `outletName`（卡内书 `extensions.outlet_name`），在预设或作者注释中使用 `{{outlet::名称}}`。同名内容按 Order 从高到低合并；未知名称展开为空，缺少名称的条目跳过。世界书内容和 Outlet 内不能嵌套出口。出口仍参与世界书预算、递归与计时；未被引用时不会自动塞入其他位置，诊断标记为未引用。最终请求预算会计入实际展开内容及重复引用。
- **显示正则**：ST 桥接模式按「全局 → 预设 → 角色卡」顺序执行；其他模式按「全局 → 角色卡」执行显示脚本。`markdownOnly` 用于显示、`promptOnly` 用于提示词，两者都勾选时两侧生效。未标记 only 的脚本在桥接模式分别处理提示词和显示副本，**不复刻 ST 直接修改原始消息的行为**。支持 `$0`/`{{match}}`、编号/命名捕获组、`trimStrings`、基础宏及 `substituteRegex`；显示宏只读，不写变量。替换后仍经过 Markdown 和 HTML 过滤；编辑与 MD/JSONL 导出保留原文。全局正则存放于 `.pitavern/regex.json`，不自动读取原版全局 settings.json 正则库或执行 STscript。
- **作者注释**：输入框左下角「＋」→「作者注释」编辑当前聊天的 `note_prompt/note_interval/note_depth/note_position/note_role`。间隔 0 关闭、1 每轮，其他值按用户轮数取模；深度 0 表示最新消息之后。保存会自动备份，保留未知字段，生成中禁止保存，过期版本提示冲突并保留草稿。注释在 ST 桥接模式生效；尚不导入原版全局/角色注释配置。
- **变量**：预设、角色描述、世界书和历史文本组装时可用 `{{setvar::金币::100}}` 写入，随后用 `{{getvar::金币}}` 读取。变量按聊天隔离，每轮组装执行宏，原始聊天文本保持不变；扫描预览、预算估算和工具检索使用副本，不额外写入。变量暂存在本轮内存中，成功后与回复一起提交；失败或停止不保存本轮宏写入。支持 addvar/incvar/decvar 宏；STscript 核心解释器与界面已提供，全局变量和完整扩展命令生态仍不支持。
- **最少激活数**：设置 → 世界书检索，填写目标条目数及最大扫描深度。目标为 0 时关闭扩展扫描；最大深度为 0 时允许扫描到历史末尾。条目独立扫描深度、计时效果、概率和预算仍生效，因此不能保证一定达到目标。世界书预算与上下文使用同一模型计数器；未知模型采用估算，诊断面板会显示计数方式和过滤原因。
- **向量世界书**：在世界书检索中启用，选择已配置的连接并填写 embedding 模型 ID。所选服务须提供 `/embeddings`；只有 ST 条目中的 `vectorized: true`（卡内书为 `extensions.vectorized`）参与语义召回，也保留关键词匹配。候选条目正文和最近对话会发送到所选服务。本地索引保存在 `<stDataDir>/.pitavern/vectors/`，按地址、模型、维度和内容区分；修改内容、切换模型或删除条目后不会继续使用失效候选。向量检索目前用于桥接模式，接管模式保留原来的工具检索方式。
- **文本补全与 instruct**：在连接上选择「文本补全（OpenAI 兼容）」，baseUrl 填到 `/v1` 等接口前缀，模型 ID 按服务实际配置。选择 ChatML/Alpaca，或导入 ST 导出的 instruct JSON；此文件不同于 OpenAI Settings 预设和 context/story-string 的 Handlebars 模板。支持普通生成与顺序群聊；不覆盖用户代写和 quiet 等 ST 特殊生成模式。群聊仍需在实际文本补全供应商上验收。模板须匹配模型，不会自动探测。
- **文本补全能力限制**：可使用简洁或 ST 桥接模式，输出协议须为原生文本，运行时不发送工具声明；Agent 接管与 `game_tool` 不可用。切换接口时界面会切换到兼容选项，服务端也会拒绝不兼容的配置。原有聊天补全接口及工具循环保持可用。

`npm run verify:compat` 使用独立合成数据和本地模拟服务，验证实际请求格式、中文流式输出、停止、变量落库、索引更新与设置保存；不调用真实供应商。每次测试的请求记录保留在 `data/test-runs/compatibility-*/`。不同供应商的模型和采样参数支持仍需使用自己的服务确认。

`npm run verify:world-display` 使用独立合成数据和本地模拟服务，验证分组、Outlet、显示/提示词隔离、注释保存冲突与请求组装；产物保存在 `data/test-runs/world-display-*/`。加上 `--preview` 参数运行 server 工作区脚本可保留本地 UI 验证服务。

## 资料库编辑与迁移

顶部「资料」打开资料库，提供三个页签：

- **世界书**：创建外部世界书、搜索／复制／增删条目、关键词和正文、启停、常驻／向量、辅助逻辑、注入位置／角色／深度、Outlet、包含组、概率与时序。启用哪些世界书以及全局扫描和预算仍在设置中选择；可从同一列表选择 JSON/PNG 角色的「卡内世界书」，编辑后保留未知字段与原图。
- **正则脚本**：编辑全局、预设和 JSON／PNG 角色卡来源的脚本，支持搜索／复制、排序、启停、作用位置／层、深度、捕获裁剪和查找宏替换。预览使用独立线程、只读变量和执行超时，只测试当前来源。斜杠命令正则位置仍只作为兼容字段保留，不会自动处理脚本源码；STscript 从聊天输入框或独立编辑器执行。
- **备份与迁移**：导出 `.pitavern.gz` 整库文件，或上传后预览文件数、分类、展开大小与时间，再恢复到同级新目录。上传、校验、导出和恢复均有阶段进度与取消入口；最终原子提交不可取消。

编辑使用内容版本校验，其他窗口或外部程序改过文件时拒绝覆盖。草稿按资料库和文件保存在浏览器本地，刷新后重新选择文件可恢复；存储空间不足时明确提示。恢复旧草稿不会跳过文件版本冲突检查。关闭或切换资料时，明确放弃会移除对应草稿。保存前把原文件备份到 `.pitavern/editor-backups/`，然后原子替换；未知字段保留。编辑 PNG 卡片只改 `chara`／`ccv3` 文本块，保留图片、其他块和未知 JSON 字段。保存后通知已连接窗口同步显示。修改资料前需停止全部聊天生成。「编辑历史与恢复」支持分页查看、并排对比和恢复旧版本；恢复前备份当前完整文件，保留 PNG 原始字节，过期版本拒绝恢复。

整库归档包含 `characters/`、`chats/`、`worlds/`、`OpenAI Settings/`、`skills/` 和 `.pitavern/`（包括聊天／编辑备份及生成活动）。向量缓存、临时文件和其他 ST 目录不包含在内。可选附带白名单便携设置（persona、上下文模式、启用的世界书／预设、扫描预算、输出协议、压缩与接管），导入时预览并单独勾选应用；默认保留本机设置。连接地址、API 密钥、默认模型、向量连接与路径始终不随便携设置迁移；新机器需自行配置连接。旧版不含设置的归档仍可恢复。归档不是加密格式，含完整私人聊天。压缩文件上限 512 MiB，单文件 32 MiB，展开总计 2 GiB，最多 10 万文件；使用 gzip 压缩的版本化 NDJSON，每个文件及归档汇总均校验 SHA-256，不跟随符号链接。

导出快照、导入校验和恢复期间服务暂停资料读写与生成。恢复会重新校验原归档、写入新目录，并原子保存新的 `stDataDir`；当前库完整保留，完成后服务保持暂停，**必须重启服务才会读取新库**。本机连接与密钥始终保留，应用设置仅在单独勾选时更新。恢复前的取消或失败不改变当前配置，已写出的部分新目录保留供核查。回退时先停止服务，把实际配置文件（默认 `data/config.json`）的 `stDataDir` 改回界面显示的旧目录，再启动。

归档及导入校验产物保留在数据目录旁的 `.<数据目录名>-maintenance/`，不会打包自身，也不自动删除；失败产物和未激活的新目录不影响当前库，「备份磁盘占用与管理」可查看容量、文件数和路径；手动移除需输入完整归档名确认，使用中的导入预览不可移除。未激活的恢复目录保持原样，不自动清理。同一进程最多保留 3 份待恢复预览，可取消不需要的预览（磁盘产物仍保留），关闭弹窗会释放预览资格；浏览器刷新可在同一服务中重新查询任务／预览；服务重启后需重新上传。验证命令 `npm run verify:library`，使用合成数据逐文件比对恢复结果；测试产物保留于 `data/test-runs/library-*/`。

实际聊天的提示词组装（含正则与世界书扫描）在 Node 工作线程执行，执行限时 2 秒，启动限时 15 秒，可停止；超时不会向模型发送请求或提交变量／计时状态。显示正则在浏览器工作线程执行，限时 1.5 秒，超时显示原文和提示；存档始终保留原文。

## 群聊与 STscript

- 侧栏「新建群聊」选择 2–12 张角色卡，按勾选顺序发言；输入框上方可选全员或指定成员。共享历史，每位使用自己的设定、卡内书和显示正则。整轮成功才提交全部回复；失败/停止回滚，候选随 JSONL 持久化。
- 输入框左下角「＋」→「STscript」打开编辑器，也可在聊天输入框输入以 / 开头的脚本。支持管道、闭包、变量、循环、消息和模型命令，详见 [兼容说明](docs/COMPATIBILITY.md)。未知命令明确报错，失败或停止时整次撤回。模型请求已产生的用量仍保留。
- npm run verify:local 在当前资料库副本上执行备份/恢复逐文件校验；加 -- --provider 明确启用一次真实默认模型请求。未配模型时报告待验并退出 2；本机样本规模如实统计。
- npm run release:pack 仅打包当前已提交 Git 源码并输出 SHA256；npm run verify:release -- /绝对路径/源码包.tar.gz 在独立空目录运行首次安装和一键启动验收。源码包不含资料库、配置、密钥或依赖。
