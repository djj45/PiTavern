# 0.9 双阶段生成与正文重写契约

状态：M1 冻结。默认关闭；只对单人、世界 enabled、工具开启、Chat Completions、native 文本生效。simple、bridge、takeover 复用结算流程。群聊、文本补全、game_tool、无世界或只读世界继续单阶段。两阶段使用同一配置模型，不引入全知模型。

## 事务与阶段

`settling → validating → rendering → committing → succeeded`。任一步可 failed / aborted；重启把未完成活动记为 interrupted，不自动恢复结算。

结算只修改内存事务。模型调用 `submit_narrative_plan` 提交场景、叙事要点、对白方向及可见引用，普通文本不完成结算。结算工具按顺序执行；提交计划必须是最后一个调用，之后封闭工具，后续调用不得再改变副本。服务端校验计划，从实际事务补入玩家可见状态、可见事件、获知事实；模型没有余额、库存、授权或成功回执的写入字段。

正文阶段独立请求，无工具声明、无工具执行；仅接收数据包、有限活动路径正文和写作设置，不接收原始模板、原始快照或 NPC 私人知识。返回工具调用、空白、异常、超预算或取消均失败。正文请求失败可按设置自动重试0–2次（默认0），同次运行沿用已校验数据包、不重跑结算；非法输出、空白、预算和取消不重试。用户重试整轮从检查点重新结算，正文重写失败可重新发起无工具重写。

同一取消信号贯穿流程。正文成功且 JSONL revision 仍相同，才一次写入正文、世界、知识、变量、计时、候选和数据包。任何失败保留先前已提交状态；用户输入可以先保存。没有持久化的“已结算、待补正文”状态。

## 数据包与恢复

协议 v1，服务端生成结算 ID、回合 ID、模板与知识视角、状态/来源指纹。保存玩家 DTO、实际可见事件、校验计划、原始本轮输入、独立方向要求及写作设置。字符串、条目、引用及总长度有界；未知字段、未知版本和悬空/不可见引用拒绝。自由叙事建议不构成硬事实或知识授权。

数据包写入回复 `extra._pitavernNarrative`，随原生 swipe、剧情候选、隐藏 continuation、JSONL 和备份保存；活动不是恢复来源。默认 HTTP、WS、诊断不输出数据包或原始提示。JSONL/备份仍是作者完整资料；MD 仍只导出活动路径正文。本地作者入口不是多人权限控制。

v1 字段为 `version/settlementId/turnId/stateHash/sourceHash/templateSourceHash/templateHash/viewpointId/knowledgeKey/state/events/plan/writing/digest`。`plan` 仅允许 scene（1000字）、beats（1–12项）、dialogue（0–12项）、references（0–32项，actor/fact/event）；每项文本1000字，引用128字。写作设置和原输入各32000字，方向4000字；事件最多100项，总包250000字符。digest 检测损坏，不是作者权限签名；导入包即使摘要自洽，也必须与重新构建的玩家投影、真实事件和当前来源完全一致才能用于重写。

正文阶段依然遵循 0.8 玩家投影。普通历史/角色卡/世界书的自由文字不自动脱敏；不做关键词清洗，也不承诺阻止公开线索推断。回退未知分支、v1 或无世界后，旧活动按记录视角与当前视角过滤，不能因当前无 v2 状态跳过。

## 两种重做

| 操作 | 世界与知识 | 正文 |
| --- | --- | --- |
| 重新生成 | 回合前检查点重新结算 | 新剧情候选 |
| 只重写正文 | 维持已提交状态，不调用工具 | 保留旧正文，追加文字候选 |

重写 API 独立，需消息 ID、选中候选、预期 revision、请求 ID 和写作要求。仅支持活动路径末尾有有效数据包的回复。校验当前状态、模板来源及回合前路径指纹；编辑历史、修正状态、迁移模板导致不匹配时拒绝，不从正文猜测结算。新正文沿用结算 ID，状态字段逐项不变；失败/停止保留旧正文和选择，不触发自动候选。相同请求 ID 与内容重放返回已提交结果；不同内容复用 ID 拒绝。生成期间重复操作拒绝。

模板迁移保留历史包原始来源，不伪装重新结算；导入、重启后重新验证资格。旧回复无包禁用重写。切换文字候选恢复同一已提交状态，不执行工具。

## 诊断与基线

活动记录阶段、耗时、模型、每阶段用量和失败位置，累计包括失败请求。恢复备份不回退实际消耗。字符估算与供应商 token 分开标注；未调用真实供应商不宣称叙述质量提升。

固定酒馆场景复用 `scripts/fixtures/knowledge-tavern.json`：100 金币购买17金币长剑，推进10分钟，出示介绍信后获知密道。连续重写三次状态不变；重新生成从100开始结算到83。单阶段基线脚本 `two-stage-baseline-verify.ts` 在三模式截取完整本地合成请求，断言两次请求和最终状态；每请求合成用量1000输入/100输出。耗时记录实测、不作跨机器阈值；真实模型质量未评测。

## 分步交付与验收

M1 契约与单阶段基线；M2 数据包与持久化；M3 结算/只读正文代理；M4 原子编排与诊断；M5 重写 API/候选/UI；M6 分支秘密导入恢复；M7 完整回归与候选包。

必须截取供应商完整请求验证无工具/无结构化私密；覆盖三模式、长局、三次重写、重新结算、失败/停止/空输出/预算/冲突回滚、重复请求、备份至 v1/无世界、HTTP/WS/分页、导入重启、390px。最后 check/build、离线回归、Chromium、准确提交 Node22/24、真实资料副本、源码包安装/HTTP/WS/端口回收；0.9 候选独立验收后再正式发布。
