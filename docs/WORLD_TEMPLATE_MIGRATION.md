# World Template Migration 0.6.0 契约

状态：0.6.0 验收候选。单快照规划、全聊天规划/原子应用、预览/应用 API 与 Web 入口已实现；最终发布需验收后打 0.6.0 标签。

## 1. 范围

0.6.0 提供：

- 版本差异：比较聊天内嵌模板与模板库目标版本。
- 迁移预览：明确显示新增/删除/修改实体、价格、初始状态和规则版本影响。
- 明确的应用入口：对指定聊天应用到目标模板版本；生成期间禁止。
- 原子写入、备份、失败不改变聊天；保留旧模板记录和其他候选。
- 更新前创建聊天备份，支持恢复。
- 切回旧分支、重生成时使用迁移后的模板版本；历史正文不重算。

不提供：

- 自动根据正文推断世界状态。
- 无确认的批量迁移所有聊天。
- 删除/修改实体 ID 的不可安全迁移变更（首版拒绝）。
- 修改初始金额/位置/库存并重置已有世界（默认只影响新聊天）。

## 2. 变更处理表

| 变更 | 首版处理 |
| --- | --- |
| 名称、描述 | 展示差异；确认后更新聊天内嵌模板记录/名称；不影响世界数值。 |
| 物品固定价格 | 展示差异；确认后未来购买使用新价格；已有余额/库存不变。 |
| 新增地点 | 加入模板目录；不改变当前位置/在场角色。 |
| 新增角色 | 以新模板初始地点创建 alive 状态；不在当前场景时不加入 presentActorIds。 |
| 新增物品 | 加入目录；不凭空生成库存。 |
| 删除地点/角色/物品 | 检查快照/审计检查点引用；首版拒绝无法安全迁移的删除。 |
| 修改实体 ID | 等同删除+新增，首版拒绝。 |
| 修改初始金额/位置/库存 | 预览标记“仅新聊天生效”；不重置已有世界，不修改当前快照。 |
| 修改规则版本 | 只接受运行时已支持且有迁移方案的版本；未知版本拒绝。 |
| 模板版本/hash | 更新快照引用；旧模板记录保留在聊天模板表，供审计/回退。 |

## 3. 快照迁移

- 源：当前活动世界快照、所有候选 `state._pitavernWorld`、所有用户回合 `_pitavernBeforeTurn.metadata._pitavernWorld`，递归进入隐藏 continuation。
- 目标快照必须：
  - 保留时钟、当前位置、玩家/已有角色状态、金额、库存和本轮事件；
  - 把 `templateHash/templateVersion/rulesVersion` 指向新版本；
  - 为新增角色补 alive 初始状态；不删除已有角色；
  - 通过新模板 `WorldState` 校验；迁移后世界必须为 enabled（模板/规则/引用完整）。
- 初始金额/位置/库存变化不写入已有快照；新增实体初始状态按新模板 `initial` 推导。
- 所有快照在同一轮聊天 JSONL 替换中写入；不能只改活动路径。
- 新模板完整记录写入 `chat_metadata._pitavernWorldTemplates`；旧记录不删除。
- 只改名称/描述（内容哈希不变）的发布也必须可迁移：更新聊天内嵌模板版本元数据，不重置世界数值；完全相同的目标只提示无需迁移。
- 源记录必须能由自身正文重新计算出一致的 contentHash，且用源模板构造的 `WorldState` 必须为 `enabled`；未知规则/模板版本、缺失角色或悬空引用都在读取目标前阻断，不能用迁移“补回”源世界。新增角色只取源模板与目标模板的 ID 差集。
- 本次迁移不新增世界审计事件；需要区分时可依赖模板版本/hash 变化。

## 4. 冲突、生成和原子性

- 生成中（任一聊天流式生成）禁止迁移；服务端 `assertIdle`。
- 提交前必须同时校验：
  - 聊天文件 revision（防止其他窗口编辑/切分支）；
  - 模板库版本/draft 未变化（按 contentHash）；
  - 目标版本仍是模板库当前发布版本，或明确选择的历史版本；
  - 迁移计划基于的源模板 hash 与聊天当前快照一致。
- 写入前自动创建聊天备份；一次 JSONL 原子替换。任一步失败，聊天正文、世界、候选、模板表不变。
- 迁移后可恢复该备份；恢复旧备份会回到旧模板版本，模板库记录仍保留。
- 迁移不改变聊天标题、角色卡关联、分支树结构、候选选中状态或正文。

## 5. 分支与重新生成

- 迁移后所有活动/非活动分支的世界快照都指向新版本；切回旧分支也使用新版本。
- 重生成使用该用户回合迁移后的 `_pitavernBeforeTurn` 快照；不会恢复旧模板。
- 历史检查点全部迁移，避免“切回旧分支又变回旧价格”的混合状态。
- 旧模板记录仍在模板表中，但不作为默认恢复来源；需要硬回退时使用聊天备份。

## 6. 数据结构与 API（0.6.0 已实现）

- 预览：`POST /api/chat/world/migrate/preview`，`{ chatId, targetHash }`；返回聊天 revision、目标摘要、每个恢复点的 changes/blocking/warnings、计数和完整 previewHash；不可迁移返回 422 + preview，无变化返回 200 + noop。
- 应用：`POST /api/chat/world/migrate/apply`，`{ chatId, targetHash, expectedRevision, previewHash }`；重新计算计划，revision/previewHash 不一致返回 409；成功一次原子替换并返回新 revision、backupId、目标摘要和计数。
- 版本差异分为 location/actor/item/template/initial/rules；每条包含 id、名称、变更类型、旧/新值摘要和是否阻断。预览哈希覆盖 from/to 的名称、描述、模板/规则版本和变更，描述单独变化也会改变 previewHash。
- 首版不提供“迁移所有聊天”入口。

## 7. 0.6.0 验收

- 价格修改：旧聊天迁移后未来购买用新价格；余额/库存/历史分支不变。
- 新增角色/地点/物品：迁移后快照可读、新实体初始状态明确；旧分支切回仍使用新版本。
- 删除/改 ID：预览阻断，不写聊天。
- 改初始金额/位置/库存：预览仅影响新聊天，已有世界数值不变。
- 未知目标规则版本、源模板正文与 contentHash 不符、源快照与源模板版本/角色不一致：阻断。
- 仅名称/描述发布：预览可应用，previewHash 随描述变化；完全相同的版本只提示无需迁移。
- 生成中、revision 冲突、模板 hash 变化：拒绝且不改变聊天。
- 迁移→重启→备份恢复→再迁移；旧模板记录保留。
- 真实供应商/大库保持 `not_requested`/未验边界。

## 8. 与 0.5.0 的关系（0.6.0 实现）

- 0.5.0 的模板库/版本选择保持不变；0.6 只新增“更新已有聊天”能力。
- 聊天仍以 JSONL 内嵌模板表为恢复权威；模板库删除/修改不自动影响旧聊天。
- 0.6 首版不重算历史正文，世界账本以快照迁移为准。
