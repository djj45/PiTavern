# 0.12.0 雾港体验修正

M1 行动可用性、M2 证据约束、M3 任务命名与 M5 分支/失败体验已在 `1bc7f9e` 独立复验通过。本次按已确认分钟表交付 M4 行动耗时，单独形成复验候选，不发布；性能压缩在体验修复后安排。

## M1 行动建议

公共交互目录增加服务端派生 `availability: {status: "ready" | "later", reasons: string[]}`。ready 表示当前快照满足交互条件及传播来源校验，仍需工具成功回执才能叙述完成；later 只能作为明确标注的后续目标。行动、日程或知识变化后重新查询，查询不执行任何交互。

模板交互可选 `publicConditionIndexes` 指向作者明确公开的条件（从 0 开始，不重复、不得越界）。默认不公开前置关系。只对公开索引显示地点、NPC在场、持有物的阻塞说明；未获知事实、NPC私人知情和内部传播来源只给通用说明，不输出秘密ID/正文、作者备注或效果。该字段不自动写入旧模板；无此字段的 v2–v4 保持旧哈希。v1不新增知识规则。

雾港公开流程明确：先核验救援，再带材料回公所找在场的林照；收集证词不代表立即可以公开。任务日志保留“先接取、每轮最多推进一个阶段”的规则，不因查询自动推进。单/双阶段、simple/bridge/takeover及缓存使用同一过滤后投影。可用性不是新的知识授权，不据此召回另一分支的记录。旧叙事包保持原样；与新投影不匹配时按原规则拒绝重写，不补造来源。

## M2 证据与叙事

案件证据只能引用当前玩家已知事实，明确区分“证人声称”“记录记载”“尚待验证的推测”和法律结论。角色卡/公共世界书不提前包含答案。环境、动作与情绪可自由描写，但不能从装饰细节推导新的证据、物品、犯罪事实或知识。未登记钥匙、物证和供认不能写成确定证据；证词不能升级为定罪。双阶段正文也遵守这一约束。

## M3 任务与里程碑

交付任务 `repair` 改名“备齐修灯材料”，交付目标明确为材料已交付，奖励和交付规则不变。“灯塔已验证”单独以 `confirm_light` 成功揭示的事实为准，不因任务完成亮灯。雾港内容1.1.0／模板v2完成此项，M4进一步升级为内容1.2.0／模板v3；旧聊天不会自动更新，规则不同的旧模板不静默改写。验证修正版请新建独立资料库。

## M5 分支与失败

历史分支用“第 N 轮 · 候选 X/Y”定位，同时显示本候选的正文摘要与原始生成时间。没有可靠时间的旧候选标记“时间未记录”，不以重启/打开时间补造。明确区分当前路线、路径中节点和未选候选；保留回到切换前路线入口。失败尝试不成为正文或剧情候选，放在生成诊断中；重试沿用未完成的用户回合，重新结算有成功回复的回合仍使用“重新生成”。累计用量包含其他候选、重试和失败，不能当成单路线成本。

首个模型请求发生上游错误时，结束该失败响应并保留原始错误供安全归类，不继续用“缺少叙事计划”覆盖失败原因，也不额外计算一次合成错误响应。错误原文仍不回显给玩家；单/双阶段均验证一次请求、一次响应、零状态/候选提交。

## M4 固定行动耗时契约（已确认）

固定行动耗时由服务端规则结算，禁止只靠提示让模型补调 advance_time。通过 v4 模板可选 `actionTime` 显式启用；字段缺失时保持原行为、原哈希，旧聊天读取不升级。雾港新内容版本启用以下固定表：

| 成功操作 | 分钟 | 计费单位 |
| --- | --- | --- |
| 移动 | 10 | 一次实际改变地点的 move_to；同地点移动 0 |
| 调查／知识交互 | 10 | 一次产生新知识或公开变化的 world_interact；多条效果仍只算一次 |
| 购买／物品转交 | 5 | 一次成功的购买／转交命令，与件数无关 |
| 接取任务 | 0 | 不推进时间 |
| 推进任务／最终交付 | 5 | 一次成功的阶段推进；内部交付及多项奖励不重复收费 |
| 明确等待 | 指定分钟 | advance_time 不另加行动耗时 |
| 查询、拒绝、幂等重放、重复已完成操作 | 0 | 不产生新的耗时 |

重复调查以持久化知识／公开状态为依据，不依赖近期事件或内存缓存；同回合与后续回合均如此。若条件已不满足则返回拒绝，仍为 0 分钟。普通叙事、重复查看和任务面板没有“首次访问耗时”；只对合法工具引起的成功变化结算。模型不得额外用 advance_time 为这些动作补时。成功回执返回本操作耗时、最终时钟和期间可见移动；玩家界面及下一工具按最终状态刷新。

执行顺序固定为：以行动开始时状态校验地点、NPC在场、物品与知识 → 在单操作私有副本结算行动 → 从原时间推进对应固定耗时，执行 `(旧时间, 新时间]` 日程 → 全部成功才替换事务暂存状态。NPC在行动后离场不反向撤销已完成行动；后续行动检查新位置。任一阶段失败（含时钟上限、日程预算）丢弃该操作的物品、金额、知识、任务和时间变化；正文失败、停止、revision冲突撤销整轮。临时任务视角在行动与每个日程触发后均观察，失败副本不污染诊断授权。查询/失败动作/幂等重放不耗时；重生成从回合前检查点结算，正文重写零耗时，候选切换恢复各自时间。

配置为 `actionTime: {moveMinutes, interactionMinutes, tradeMinutes, questAdvanceMinutes}`，各项为 0–1440 的整数，仅 v4 允许；雾港固定为 10/10/5/5。接取恒为 0。显式迁移新增／变更耗时规则只影响未来操作，预览必须说明不补扣历史、不改变当前时钟或日程进度；各恢复点保留自己的世界状态。旧叙事包仍按原来源校验，迁移后不匹配不能重写。

专项覆盖 NPC 在行动结束时离场仍可完成开始时合法交付、开始时不在场拒绝；跨午夜；时间与日程上限无部分结算；重复调查跨重启与事件裁剪；三模式单／双阶段，正文失败、停止、冲突、重试、请求重放、重生成、三次重写及候选／隐藏后续／备份／导入恢复。真实供应商仍为 `not_requested`。
