# 0.12.0 雾港体验修正

本轮先交付 M1 行动可用性、M2 证据约束、M3 任务命名与 M5 分支/失败体验，停在可复验修正版，不发布。M4 行动耗时单独实现、单独验收；性能压缩在体验修复后安排。

## M1 行动建议

公共交互目录增加服务端派生 `availability: {status: "ready" | "later", reasons: string[]}`。ready 表示当前快照满足交互条件及传播来源校验，仍需工具成功回执才能叙述完成；later 只能作为明确标注的后续目标。行动、日程或知识变化后重新查询，查询不执行任何交互。

模板交互可选 `publicConditionIndexes` 指向作者明确公开的条件（从 0 开始，不重复、不得越界）。默认不公开前置关系。只对公开索引显示地点、NPC在场、持有物的阻塞说明；未获知事实、NPC私人知情和内部传播来源只给通用说明，不输出秘密ID/正文、作者备注或效果。该字段不自动写入旧模板；无此字段的 v2–v4 保持旧哈希。v1不新增知识规则。

雾港公开流程明确：先核验救援，再带材料回公所找在场的林照；收集证词不代表立即可以公开。任务日志保留“先接取、每轮最多推进一个阶段”的规则，不因查询自动推进。单/双阶段、simple/bridge/takeover及缓存使用同一过滤后投影。可用性不是新的知识授权，不据此召回另一分支的记录。旧叙事包保持原样；与新投影不匹配时按原规则拒绝重写，不补造来源。

## M2 证据与叙事

案件证据只能引用当前玩家已知事实，明确区分“证人声称”“记录记载”“尚待验证的推测”和法律结论。角色卡/公共世界书不提前包含答案。环境、动作与情绪可自由描写，但不能从装饰细节推导新的证据、物品、犯罪事实或知识。未登记钥匙、物证和供认不能写成确定证据；证词不能升级为定罪。双阶段正文也遵守这一约束。

## M3 任务与里程碑

交付任务 `repair` 改名“备齐修灯材料”，交付目标明确为材料已交付，奖励和交付规则不变。“灯塔已验证”单独以 `confirm_light` 成功揭示的事实为准，不因任务完成亮灯。雾港内容版本升级；旧聊天不会自动更新，规则不同的旧模板不静默改写。验证修正版请新建独立资料库。

## M5 分支与失败

历史分支用“第 N 轮 · 候选 X/Y”定位，同时显示本候选的正文摘要与原始生成时间。没有可靠时间的旧候选标记“时间未记录”，不以重启/打开时间补造。明确区分当前路线、路径中节点和未选候选；保留回到切换前路线入口。失败尝试不成为正文或剧情候选，放在生成诊断中；重试沿用未完成的用户回合，重新结算有成功回复的回合仍使用“重新生成”。累计用量包含其他候选、重试和失败，不能当成单路线成本。

## M4 待单独实现的规则

固定行动耗时必须由服务端规则结算，禁止只靠提示让模型补调 advance_time。本修正版仍仅在明确等待时推进时间。

后续执行顺序固定为：以行动开始时状态校验地点、NPC在场、物品与知识 → 在事务副本结算行动 → 从原时间推进对应固定耗时，执行 `(旧时间, 新时间]` 日程 → 一起暂存。NPC在行动后离场不反向撤销已完成行动；后续行动检查新位置。任一阶段失败（含日程预算、正文失败、停止、revision冲突）整体撤销。查询/失败动作/幂等重放不耗时；重生成从回合前检查点结算，正文重写零耗时，候选切换恢复各自时间。移动、调查、交易等的分钟表及重复调查是否收费，须在 M4 专项中冻结后才启用。

## 复验记录

固定合成场景验证提前公开阻塞、救援后回公所引导、错误地点/错过NPC、材料交付与验灯分离、失败回滚、重试、重生成、切候选及重启。检查实际本地模拟供应商请求中的可用性与秘密边界。合成结果不代表真实模型遵守建议或叙事质量提升。

真实模型两条结局、模型/参数/每轮耗时/请求数/输入/输出/缓存/失败重试与费用另立记录。本轮未授权供应商调用，标为 `not_requested`，不把此前累计约48.6万tokens解释为一条路线成本，不在修正前盲目压缩证据上下文。

本修正版本地验证：check/build、29套完整离线回归、73项Chromium通过。`verify:game` 包含7组行动投影边界和39项雾港游戏检查；分支专项另含4组时间来源/旧swipe兼容检查。浏览器覆盖材料任务新名称、分支回合/序号/摘要/时间、390px正文失败后的回滚与重试（不增加用户回合/失败候选，购买与时间仅结算一次）。供应商请求证明输入包含实时可用性与证据约束，不据此断言真实模型输出遵守规则。准确提交CI与源码包结果保存在 `data/test-runs/` 的本次复验记录中。
