# 0.8.0 知识与秘密契约

## 产品边界

世界事实是作者确定的正文；角色知识是角色已经获知的事实集合，不改变事实本身。玩家可见内容为模板公共事实、运行时已公开事实，以及模板初始玩家角色已知事实。作者视图是明确进入的本地管理界面，可查看/编辑完整定义和知情关系；不是多人权限系统。

继续使用玩家可见的单阶段叙事模型。NPC 私人知识只供服务端规则判定，不传给该模型要求保密。不实现误解、谎言、遗忘、关系变化、NPC 自主行动、双阶段生成。角色卡、世界书、宏、变量、作者注释及既有历史正文不会自动识别秘密；受保护内容必须放入本契约的结构化字段。公开目录名称/ID 本身是作者选择公开的信息，不能在这些标签中填写秘密正文。

## v2 数据字段与限制

v1 保持严格原结构、原哈希、原规则和执行能力，读取不升级。v2 使用 `schemaVersion: 2`，保留硬状态结构与 `rulesVersion: 1`，增加：

- 模板 `facts: {id,text,visibility:"public"|"restricted",description?}[]`：description 是作者内部备注，任何玩家视图都不返回。事实 ID 稳定，正文确定。最多 256 条，正文 2000 字、备注 2000 字。
- 模板 `initial.knowledge: {actorId,factId}[]`：仅影响新聊天，最多 2048 条，不重复，角色/事实必须存在。
- 模板 `interactions: {id,name,description?,conditions,effects}[]`：最多 128 条。公开目录仅输出 id/name；description、条件和效果为作者内部定义，不能随目录发送。名称最多 100 字，备注 2000 字。每次交互最多 16 个条件与 16 个效果（至少一个效果）。
- 条件为 AND 组合：`{type:"at_location",locationId}`、`{type:"npc_present",actorId}`、`{type:"has_item",itemId,quantity}`、`{type:"knows_fact",actorId,factId}`。位置、持有物条件固定指向玩家；NPC 必须 alive、与玩家同处一地；知识条件可检查任一指定角色的私人知识。公共/已公开事实视为所有角色已知。
- 效果：`{type:"learn",factId,actorId,fromActorId?}` 或 `{type:"publish",factId}`。learn 向指定角色传播；fromActorId 存在时必须确实知情且在场可交互，否则整次交互失败；不指定来源代表作者定义的发现规则。允许 NPC 向玩家告知或玩家向 NPC 告知，但发现不会自动传播。
- 快照 `knowledge: {actorId,factId,source:{type:"initial"|"interaction",turn,interactionId?,fromActorId?}}[]`、`publishedFactIds:string[]`，最多 2048 条关系和 256 条公开事实。事件增加 `knowledge_learn` / `knowledge_publish`，带 factId/interactionId，进入现有 recentEvents 上限。所有引用校验，无悬空事实/角色/交互。

模型专用 DTO 为玩家投影视图，只含公开硬状态目录、当前可见事实（含获知来源）与公共交互目录，不含完整模板、知识关系表、未揭示事实 ID/标题/正文/备注或内部规则。指定角色视图使用相同纯函数投影，但只允许作者预览；普通模型与玩家接口不能指定 NPC 视角。作者视图提供完整模板/快照，不复用模型 DTO。

## 规则与事务

`world_interact({interactionId})` 只允许选择公开交互 ID，玩家身份由绑定模板决定。拒绝额外 factId/actorId/授权字段；不能通过 world_command 直接设置知识，正文和历史摘录不能授予知识。条件失败/不存在/只读使用通用拒绝说明，不返回失败条件、秘密正文、内部描述或事实 ID。

规则先在副本检查全部条件和传播来源，再一次暂存全部效果；整轮成功才提交，失败、取消、停止均撤销。已有知情/公开关系不重复写入，不重复产生事件；同事务重复交互是 no-op。查询只读，不执行交互。工具后本轮暂存知识立即进入后续模型请求，失败后的存档仍保持回合前状态。

## 信息出口清单

| 出口 | 默认视图与边界 |
| --- | --- |
| simple/bridge/takeover 系统注入、权威快照 | 玩家专用 DTO；禁止序列化原始 v2 快照/模板 |
| world_query 所有 section、world_interact 与工具错误 | 玩家视图/通用失败；不返回完整条件或 NPC 私人知识 |
| HTTP 聊天快照/状态、WebSocket 快照/工具活动 | 玩家视图，完整私有关系不进入额外元数据 |
| 活动诊断、0.7 来源摘录/缓存 | 过滤后建索引；缓存绑定视角/知识状态，不能复用其他视角结果 |
| 历史召回、MD 导出 | 仅活动路径可见正文；不读取世界私有字段或未选 continuation |
| 模板编辑/预览、世界作者查看/修正、迁移差异 | 明确作者入口，可查看全部；不自动在玩家窗口加载作者快照 |
| JSONL 导出、聊天备份、整库导出 | 完整存档，含全部秘密；作者界面提示。分享脱敏导出不在本版 |

不做历史字符串替换清洗。已写进正文/旧活动记录的秘密不能可靠收回，也不承诺消除模型从公开线索推断秘密。模板缺失/坏引用时玩家投影 fail closed，不输出任何私有字段或内部校验细节。知识状态只由结构化服务端快照授权。

## 兼容、迁移与恢复

v1→v2 仅显式发布 v2 目标并通过全聊天迁移预览/备份/原子应用。保留源表只读校验，任一坏恢复点阻断整体，不返回部分写入。活动、候选、回合前检查点、原生 swipe 和隐藏 continuation 各自保留知识。

新增受限事实或修改初始知情只影响新聊天；迁移不把 initial.knowledge 写进旧快照，预览明确警告。现有事实正文/可见性修改、删除或改 ID 阻断，不能静默改写记忆、公开秘密或假装撤回。增加公共事实对所有路径可见；交互条件/效果调整只影响未来执行，不撤销已经获得的知识。v2→v1 阻断。新增 NPC 不自动获得模板初始知识。

## 固定场景与分步验收

`apps/server/scripts/fixtures/knowledge-tavern.json` 固定“酒馆密道”：公共事实“旧酒馆正在维修”；掌柜知道壁炉后密道；玩家持有介绍信、位于酒馆且询问掌柜后获知。另一候选没有介绍信则未知；旁观 NPC 不自动获知。

M1 锁契约/夹具；M2 数据/严格校验/纯投影；M3 交互与事务；M4 三模式/工具/缓存/玩家出口；M5 v1/v2 迁移及分支恢复；M6 模板作者编辑、视角预览与玩家已知线索；M7 请求级泄漏检查、生成闭环、全回归/浏览器/Node22/24/真实副本/最终包验收。每步独立提交复验。

验收截取本地合成供应商的完整请求（提示、工具结果、后续调用），逐项检查受限正文、事实 ID 和作者备注在揭示前均不存在；检查暂存可叙述、失败不落盘、幂等、越权、角色差异、分支/重生成/导入/重启/恢复/迁移与原有硬状态。真实模型回答质量独立人工验收，未调用供应商不计通过。
