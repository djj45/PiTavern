# 0.7.0 兼容范围

这是独立实现，支持以下常用数据和脚本核心，并非 SillyTavern 全量替代。未配置真实模型或缺少真实大库时，不声称已完成这两项实机验收。

## 长局上下文（0.7.0）

- simple、bridge、takeover 共用带来源的纯函数工作集；接管窗口外历史参与摘录候选，桥接预设中的非历史指令完整保留。
- 不改 JSONL 格式、完整消息、候选、工具执行或回合提交语义；硬状态以当前世界快照为准，旧摘录仅作叙事证据。
- 缓存为可丢弃的进程内索引，导入/导出和备份不需要携带缓存。新增诊断随原有活动记录保存，旧记录继续可读。
- 规则提取有数量与长度上限，不能替代完整历史召回，也不保证真实模型遵守所有事实；真实模型另行验收。详见 [上下文契约](CONTEXT_CONTRACT.md)。

## 角色卡和世界书

- JSON/PNG V2/V3 卡片；资料库同时编辑外部世界书与角色卡内 character_book，包含搜索、复制、冲突检查、草稿和历史恢复。
- 单角色开场白：首次发言前，输入框底部「开场白」按钮可打开开局列表，选择角色卡的默认／备用开局，兼容已有聊天开场的原版 swipes。选中正文保存到聊天、用于后续请求，刷新和重启保留；切换有备份和版本冲突检查。默认介绍页的编号目录可作标题。首条用户消息之后按钮隐藏，群聊不提供开局切换，卡内自定义 HTML／脚本翻页不在此兼容范围内。
- 编辑保留未知字段、PNG 像素及其他文本块；同一角色正则与世界书共用文件版本，避免相互覆盖。
- CharX：读取 card.json 与内嵌资源，识别主头像；保存原始归档、所有资源和导入清单。不联网下载远程资源，不提供资源播放/回写归档功能。
- BYAF：转换角色、场景设定、开场、示例、指令、世界书与场景聊天，保留选中回复和候选。多场景分别保留上下文。多角色归档目前仅导入首位并给出警告，完整原始归档留存，不自动转换群聊。
- 归档导入拒绝同名角色、路径穿越、重复条目、链接、文件重叠、无效 CRC、加密、ZIP64 和超限展开；上传上限 24 MiB、单文件 32 MiB、展开总量 128 MiB、最多 2000 条。归档和失败产物保存于资料库 .pitavern/imports/<id>/。
- 角色卡管理页（0.6.0）集中编辑描述、性格、场景、默认/备用开场白、示例对话、系统提示、标签；导入/复制/删除/导出原格式文件。名称不可改；PNG 像素、V2/V3 数据块和未知字段保留；保存使用文件哈希冲突检查并备份。删除卡片不级联删除聊天。卡内世界书/正则仍由「资料」编辑。契约见 [角色卡管理](CHARACTER_MANAGER.md)。
- 「开始新对话」位于角色选择区下方；必须先选中一张角色卡，按钮显示角色名和上方世界模板，不再自动使用第一张卡。

## 世界模板迁移（0.6.0）

- 入口在世界状态面板「更新模板」；选择同一自定义模板的其他已发布版本，预览后应用。
- 迁移覆盖活动世界、所有候选状态、用户回合 `_pitavernBeforeTurn` 检查点、原生 swipe_info 和递归隐藏 continuation；每个恢复点使用自身模板哈希对应的源记录。
- 任一恢复点源世界只读/源模板缺失/异模板/未知规则/坏快照都会阻断整份计划，不写入聊天。
- 应用前自动创建聊天备份；一次原子替换 JSONL，旧模板记录保留；同内容哈希只更新名称/描述时不新增内容版本。
- 预览绑定聊天 revision、目标记录和完整 previewHash；聊天或目标元数据变化后旧预览返回 409。
- 初始值变化只影响新聊天；历史金额、库存、时间、正文、变量、分支/候选顺序不改。切候选/重生成也使用迁移后的快照。
- 单文件聊天导出/导入和整库备份保留模板表与迁移后的快照；迁移前备份沿用现有聊天备份恢复入口。

## 聊天列表与界面元数据

- 侧栏对话项的「⋯」菜单支持置顶、重命名、归档和删除。重命名、置顶、归档写入聊天 JSONL 头部的 `chat_metadata._pitavernTitle`、`_pitavernPinned`、`_pitavernArchived`；不改变消息正文、候选分支、生成记录或输出路径，原版酒馆会忽略这些未知元数据。
- 归档只影响侧栏显示（列表仍由服务端返回），可在「已归档 (N)」区域取消归档；删除才移除 JSONL 文件，并在二次确认后执行。
- 聊天顶部角色名/消息数/操作行已移除；STscript、作者注释、备份与恢复、导出 MD/JSONL 位于输入框左下角「＋」菜单，菜单向上展开。
- 显示层宏：消息渲染前以只读环境展开 `{{user}}`、`{{char}}`、`{{persona}}`、`{{getvar}}`、`{{lastusermessage}}` 等宏；`{{setvar}}`、`{{addvar}}` 等写入宏只读执行或忽略。JSONL、编辑框和发往模型的原文不被改写。
- 聊天配色：设置里的角色回复色/默认对白色为空时跟随主题 / 强调色，写入连接配置的 `appearance`。对白由可配置的成对符号在显示层识别并包裹为 `span.tavern-dialogue`，不改变 `mes` 原文；每组符号可单独设色，未设色时使用默认对白颜色；默认「」和“”，最多 20 组自定义符号。思考内容不再单独设色。
- 思考强度：设置 → 模型列表按行保存每个模型的 `thinkingLevel`（关闭/最低/低/中/高）；未设置时回退到全局 `thinkingLevel`。非关闭等级视为推理模型，输入框底部的「推理」下拉框可切换并更新该模型；中转站或关闭等级的模型不显示该控件。随 pi 的 thinking level 透传给上游，上游是否真正支持对应强度取决于供应商。
- 模型连接设置采用分区表单和表格：名称/接口类型/API Key/API 请求地址，以及逐行的菜单显示名、实际请求模型、上下文窗口、最大输出、思考等级、Token 计数和删除；默认模型用行首单选切换。没有模型、密钥且地址仍是占位符的空白草稿默认隐藏，点「添加」才显示，保存时不会落库。
- API 请求地址粘贴时会折叠重复的 `https://`；官方 DeepSeek 在关闭思考时显式发送 `thinking: {"type":"disabled"}`，避免服务端默认思考导致极短探活没有正文。

## 聊天导入

导入单文件聊天 JSONL 的完整契约、字段和验收矩阵见 [聊天导入契约](CHAT_IMPORT.md)；这里只列兼容边界。

- **支持格式**：PiTavern「导出 JSONL」生成的原文件、SillyTavern 单聊天 JSONL，以及首个有效行就是消息的无头 JSONL（导入时补新头并警告）。允许 UTF-8 BOM，CRLF 规范化为 LF；扩展名不参与校验，内容按 JSONL 解析。不接受 JSON 数组聊天、原版 `groups/` 群组文件、Markdown/HTML 导出和 ZIP。
- **严格校验**：头部只能出现在第一个非空行，之后每个非空行必须是消息对象；损坏 JSON、半截行、其它 JSON 值、`__proto__` 字段和超限直接拒绝，不沿用普通聊天读取“跳过坏行”的行为。预览与导入共用解析器，导入端重新解析字节并校验 SHA-256 与角色存在性。
- **限制**：文件 32 MiB、物理行 200000、单行 JSON 嵌套 512 层、分支嵌套 64 层、候选节点 10000（`_pitavernReplies` 与原生 `swipes` 共用预算；单条 swipes 超限或同回合无目录时跨消息累计超限都拒绝）；预览最多返回 50 条错误并附总数。超限或编码错误在文件级拒绝。
- **角色关联**：必须选择一张已有角色卡；它成为头部的 `character_name`，消息行里的 `name` 不改写，`user_name` 原样保留。角色卡不在资料库时预览标记并给建议，用户仍可用任意已有卡关联。群聊成员配置无效时拒绝；成员缺卡只警告，补齐前不能正常生成。
- **字段保留**：消息/`extra`/头/`chat_metadata` 的未知字段、`swipes`/`swipe_id`/`swipe_info`、候选、隐藏 continuation、变量、世界快照和模板表原样保留。`swipe_info[].extra` 与消息 `extra` 使用同一套扩展字段/世界快照/候选校验；首行带 `mes` 字段（即使类型非法）按消息校验，不当作聊天头。头部只改写 `character_name`、`chat_metadata._pitavernTitle` 和 `_pitavernImport`；无头文件补新头（必要时补默认 `user_name`）。
- **世界状态**：结构损坏的世界快照拒绝导入并定位行/字段；模板表缺失、引用记录缺失、哈希/版本不匹配或规则版本未知时按 `WorldState` 契约标为只读并警告，不拒绝、不静默套用新模板。查看世界不受影响；只读状态下不能提交世界命令。
- **重复与标题**：以原始文件字节的 SHA-256 识别重复；已通过 PiTavern 导入的同一文件再次导入会阻止并返回已有聊天，不覆盖任何聊天。索引在 `<stDataDir>/.pitavern/chat-imports/index.json`，随整库备份；索引损坏时保留副本并重建。手工复制进 `chats/` 的文件不进入索引，不保证识别。标题优先保留原 `_pitavernTitle`，否则用上传文件名去掉扩展名；重名自动追加 ` (2)`、` (3)`……，可在预览中修改。
- **错误与原子性**：预览返回 `valid`、错误总数和截断后的错误；错误定位到 1-based 物理行号，文件级错误无行号。全部校验通过后才写文件：同目录临时文件 + 原子发布，失败清理；索引写入失败会删除刚创建的聊天，不留下半成品。
- **单文件不包含**：角色卡 PNG/JSON 及卡内世界书（仅保留聊天内引用的模板表）、独立生成记录/用量/工具活动、供应商连接/API Key/模型设置/persona/全局世界书/正则/预设，以及聊天备份历史、导入索引等服务端管理元数据。完整迁移请使用「资料 → 备份与迁移」整库归档。

## 世界模板库

完整契约见 [世界模板契约](WORLD_TEMPLATES.md)。

- 模板库保存在 `<stDataDir>/.pitavern/world-templates/`：草稿索引 + 不可变版本文件，随整库备份/恢复。
- 模板列表、新建空白、从内置复制、导入/导出 `pitavern-world-template` v1、删除；导入时模板 ID 与已有/内置冲突会分配新 ID。
- 草稿保存使用 revision 冲突检查；发布生成新版本，仅有名称/描述变化时更新发布元数据、不增加内容版本。
- 新聊天可选择最新已发布模板，或通过 `worldTemplateHash` 选择精确版本；聊天把完整模板记录写入自身 JSONL。
- 已有聊天/分支不随模板修改、发布或删除改变；删除模板库条目只影响新聊天选择。
- 模板编辑器覆盖地点/角色/物品固定价格、初始玩家/地点/金额/库存和初始世界预览；编辑器未保存修改有二次确认。
- 0.6.0 起可通过世界状态「更新模板」迁移已有聊天；0.5.0 不提供该入口。

## 聊天分支与重新生成

- 每次重新生成把旧回复保留为候选；同一用户回合的候选组成分叉点，可回到任意历史回合切换。活动路径仍写入 JSONL，未选中分支的后续剧情和状态以原始 JSONL 行保存在该用户消息的 `extra._pitavernReplies`，切回时恢复。原版酒馆只看到当前活动路径，不保证识别该扩展。
- 分支管理窗口读取活动路径和各候选 `continuation`，建立包含非活动路线的完整目录；节点按完整选择路径生成稳定 ID，新候选持久化 `branchId`。目录只读预览，跨层切换由服务端一次解析祖先路径并原子写入。预览按路线读取原始 `mes` 消息并分页加载，不执行 Markdown、显示正则或宏展开，也不写回存档。无 `messageId` 的旧存档首次打开目录时会**递归**补齐活动消息、候选 messages 和 continuation 内的持久 ID，并迁移旧分支元数据键；迁移后会广播聊天快照，旧 `line-N` 编辑仍兼容。跨层路径与目录深度统一上限 200。正文搜索按每页 100 条返回，前端可继续加载后续命中；新查询会使旧分页响应失效。
- 路线名称、备注、标签、收藏和归档元数据保存在 `chat_metadata._pitavernBranchMeta`；目录缓存按聊天版本失效。点击「继续这条路线」才切换，失败时原 JSONL 和活动路线不变。归档以整棵子树隐藏，可在「已归档」页签恢复；批量收藏/归档一次写入。
- 路线对比展示两条路线的路径、轮次范围、标签和末段预览，不执行完整正文 diff。
- 切换候选会同时恢复该分支末端的变量、状态投影、世界书计时和召回计数检查点。分支后续中继续生成的新回合仍属于该分支；切换不会回滚已发生的 token 用量。
- 设置「剧情分支与自动候选」可在每次成功回复后自动追加 0–4 个候选；每个候选是一次独立的模型调用，可停止。该功能只影响生成次数，不改变 JSONL 结构。
- 「换条路线」的方向要求只随本次请求作为临时 system 内容发送，不写入聊天消息或元数据。自动候选和手动重新生成失败/停止时保持原回复与分支状态。
- 备份与恢复包含全部分支数据。**JSONL 导出原样返回整份聊天文件**，包含当前活动路径、未选中的候选、隐藏 continuation、变量、世界快照/模板表、群聊和分支元数据；**MD 导出只包含当前活动路径的可见消息**，不含候选、隐藏 continuation、世界模板表或生成记录。两者都不包含角色卡、独立生成记录和供应商配置。编辑消息、添加/插入消息或改变变量可能使旧的候选检查点失效。不同聊天窗口同时切换分支时会做版本检查并拒绝过期写入。

## 群聊

- 2–12 个不同角色，按勾选顺序全员发言，或每轮指定成员；成员从已有卡片选择。
- simple、bridge、takeover 复用原上下文流程；桥接模式遵守预设 marker 开关。各角色用自己的设定、卡内书和显示正则，历史标记发送者。
- 一次用户发言、整轮原子提交；中途失败/停止不保存角色半轮回复。普通发送保留用户消息供重试。
- 重生成沿用原轮发言角色，候选包含整轮多角色回复与状态；任意历史回合均可切换候选，未选中分支的后续剧情与状态会保留。重启与 JSONL 导出保留元数据，原版酒馆未必识别这些扩展。
- 当前不读取原版 groups/group chats 目录，不提供自动自然轮换、随机插话、成员中途编辑。BYAF 多角色自动迁移也不在本版范围。

## STscript 核心

入口：输入框左下角「＋」→「STscript」编辑器，或聊天输入框的 / 开头文本。普通斜杠文本可用 /send /你的文本 明确发送。

| 类别 | 已实现 |
| --- | --- |
| 语法 | 管道、双竖线清管道、双引号、反斜杠转义、双斜杠及块注释、闭包 {: ... :}、命名闭包 /:name、命名参数和默认值 |
| 流程 | /pass、/echo、/return、/break、/abort、/run、/if、/while、/times、/foreach、/delay |
| 作用域 | /let 声明、/var 读写、宏 var；闭包遮蔽与祖先变量访问 |
| 聊天变量 | /getvar、/setvar、/addvar、/incvar、/decvar、/flushvar；get/set 支持 index= JSON 数组/对象索引 |
| 条件 | eq/neq/lt/gt/lte/gte/not/in/nin，支持数值、作用域或聊天变量、文本 |
| 数学 | add/mul/max/min/sub/div/mod/pow/sin/cos/log/abs/sqrt/round/floor/ceil；无效运算或无限结果返回 0 |
| 字符串/JSON | len/trim/trimstart/trimend/tolower/lower/toupper/upper/replace/split/join；replace 是字面替换 |
| 消息 | /messages names=on/off 0-3、/send、/sendas name=角色、/sys、/comment；支持 at= 插入。comment 为不进入上下文的隐藏行 |
| 模型 | /gen 当前上下文生成到管道；/genraw 原始提示；/trigger 为当前角色/群聊全员生成并追加，支持 name= 指定群成员 |
| 宏 | 已有基础宏、getvar/setvar/addvar/incvar/decvar，及 pipe/timesIndex/lastMessageId/lastMessage |

示例：

    /let label 本轮分数 |
    /setvar key=score 0 |
    /times 3 {: /incvar score :} |
    /if left=score right=3 rule=eq else={: /abort 分数错误 :} {:
      /sendas name={{char}} {{var::label}}：{{getvar::score}} |
      /echo 已完成
    :}

    /let multiply {: a=2 b=3 /mul {{var::a}} {{var::b}} :} |
    /:multiply a=4 b=5 |
    /echo 结果为 {{pipe}}

foreach 使用 JSON数组或对象加闭包，闭包内提供 var::item、var::index、var::key，输出结果数组。times 提供从零开始的 timesIndex。闭包第一条命令不隐式接收父管道，可显式使用 pipe 宏。

### 事务与限制

- 脚本在聊天/变量副本执行，成功后原子保存并备份。失败、取消或版本冲突不保存部分消息/变量，未知原始行仍保留。
- 每个聊天禁止脚本与普通生成并发。编辑器或聊天「停止」可取消；模型已发生的费用不能回滚，活动记录保留。
- 添加/插入消息或改变变量会清理失效的旧候选检查点、投影和计时缓存。脚本 trigger 不创建普通候选目录；需要候选时使用普通生成。
- 最多 20 万源码字符、1 万步、60 秒、32 层闭包、每值/变量合计 100 万字符、最多新增 100 条消息、100 条 echo。循环默认最多 100 次；guard=off 仍受全局上限约束，foreach 最多 1000 项，delay 最多 5 秒。
- 不执行任意 JS、shell、扩展命令、全局变量、DOM 操作、远程加载脚本、弹窗输入或立即执行闭包。未实现命令和命名参数明确报错，不能把任意原版脚本称作已兼容。
- 模型命令使用配置快照，不开放工具执行；桥接复用预设组装，但脚本生成暂不执行向量召回和世界书计时推进。普通群聊使用完整原生成流程。
- echo 的 title/severity 作为兼容参数接受，统一显示文本；不复刻原版弹窗样式。斜杠命令正则位置不自动应用到脚本。

语法依据：SillyTavern 官方 [STscript Language Reference](https://docs.sillytavern.app/for-contributors/st-script/)。实现为独立解析器，不使用 eval。
