# 0.9 双阶段合成验收

这些结果来自本地合成 Chat Completions 供应商，使用真实编排、工具、HTTP/WS、JSONL 与候选。供应商每响应固定返回1000输入/100输出 token，用于验证累计统计，不能作为真实账单或模型效率结论。耗时是本机 Node26 的一次观测，不作跨机器阈值，也不宣称叙述质量提升。

## 固定场景对照

同一酒馆场景：100金币购买17金币长剑，推进10分钟、获知密道；单阶段与双阶段均通过四项硬状态检查。正文重写只需一次请求、零工具，状态字节表示不变。输入字符为实际请求 JSON 总长（包含工具声明），不等同于 token。

| 模式 | 流程 | 请求数 | 输入 JSON 字符 | 耗时ms | 合成输入/输出token |
| --- | --- | ---: | ---: | ---: | ---: |
| simple | single-stage | 2 | 15223 | 66.7 | 2000/200 |
| simple | two-stage | 3 | 23493 | 26.8 | 3000/300 |
| simple | rewrite | 1 | 6267 | 8.8 | 1000/100 |
| bridge | single-stage | 2 | 14289 | 46.3 | 2000/200 |
| bridge | two-stage | 3 | 22459 | 52.1 | 3000/300 |
| bridge | rewrite | 1 | 6167 | 7.3 | 1000/100 |
| takeover | single-stage | 2 | 15699 | 10.0 | 2000/200 |
| takeover | two-stage | 3 | 24257 | 18.5 | 3000/300 |
| takeover | rewrite | 1 | 6555 | 7.0 | 1000/100 |

观测原始数据保存在 `apps/server/scripts/fixtures/two-stage-comparison.json`；`verify:two-stage` 每次重新生成独立报告，不修改冻结观测。M1 单阶段基线仍单独保留。双阶段多一个正文请求；收益是结算状态固定后可单独改写文字，未证明真实模型文笔改善。

## 专项与发布候选边界

`npm run verify:two-stage` 共75组：单阶段基线3、数据包7、代理6、原子编排11、重写19、恢复7、兼容与长局边界21、对照1。覆盖三种模式及100/500/1000回合，连续三次改写、状态逐项一致、普通文本不可结束结算、计划后封闭工具、无工具正文真实请求、非法输出、取消、预算、严格revision冲突、请求幂等、原生swipe/隐藏后续、导入重启、模板迁移、v1/无世界恢复后的HTTP/WS/跨页过滤与用量保留。

新增3项 Chromium：真实双阶段和三次改写/重新结算请求；390px两种操作、停止和布局；默认关闭与设置持久化。完整浏览器共66项。完整离线回归共26组套件，其中知识53组、长局28组仍保留。

最终发布候选还须执行 check/build、完整离线/浏览器、准确提交Node22/24 CI、真实资料副本和最终源码包的全新安装/HTTP/WS/端口回收。独立验收通过前不发布0.9.0标签或正式包。真实供应商未调用；真实模型叙事质量与角色知识遵守另列人工验收。
