# 0.6.0 发布与升级（验收候选）

状态：验收候选，尚未创建 v0.6.0 标签或 GitHub Release。以下验收通过后再生成最终源码包和发布记录。

0.6.0 交付已有聊天的世界模板迁移闭环：活动世界、所有候选、回合检查点、原生 swipe 镜像和隐藏 continuation 逐个规划，验证源/目标后一次原子替换 JSONL；迁移前自动备份，旧模板记录保留。世界状态面板可以预览实际差异、阻断位置和受影响恢复点，应用后可打开本次备份。另有角色卡管理/新建空白角色、对话入口、API 地址与 DeepSeek 关闭思考、JSONL 下载扩展名修复。

## 升级

0.5.x → 0.6.0 不自动迁移聊天数据。

1. 停止生成，整库备份并确认 `stDataDir`；已有聊天、角色卡、世界书和模板库按原格式读取。
2. 切换 v0.6.0 提交后执行 `./start.command`，构建前端并重启。
3. 模板迁移只作用于明确操作的单个聊天；不会批量改写所有聊天，也不会改写历史正文。
4. 迁移前创建聊天备份；可用输入框「＋ → 备份与恢复」按 backupId/时间恢复。恢复是普通聊天备份恢复，不改模板库。
5. 同 hash 仅改名称/描述时，聊天模板表会更新元数据；旧的同一 hash 元数据不并存，需要保留旧显示信息时使用迁移前备份。
6. 迁移覆盖所有活动/非活动候选、用户回合检查点和隐藏后续；切回旧分支或重生成也使用新模板。
7. 初始金额/位置/库存变化只影响新聊天；当前世界数值、库存、时间、变量和正文不变。
8. 删除/修改实体 ID、未知源/目标规则、源模板哈希不符、缺失源记录或坏快照会阻断整份迁移。

回退时停止服务，切回升级前提交并按锁文件安装；数据回退用 0.6.0 前的整库备份或聊天备份，不能覆盖当前库。模板库版本是追加记录，0.5.x 可读取旧聊天内嵌模板。

## 边界

- 0.6.0 不提供批量迁移全部聊天、自动根据正文推断世界、删除/改实体 ID 的自动修复，也不改变角色卡/世界书/供应商配置。
- 世界迁移 API 只接受已发布目标版本；内置模板没有模板库版本列表时不在世界面板展示更新入口。
- 真实大库、第三方复杂预设和真实供应商仍未作为本次自动验收通过项。
