# 0.10.0 候选与升级

本候选聚焦任务系统第一版。0.9.0 发布提交 `aff72aafd02b8b91237c0bc0d17df6d431570df9` 冻结，任务从该提交的独立分支交付。独立复验前不打 0.10 标签、不发布。字段与规则见 [WORLD_QUESTS.md](WORLD_QUESTS.md)，合成覆盖见 [QUEST_ACCEPTANCE.md](QUEST_ACCEPTANCE.md)。

作者可配置最多 8 阶段的线性任务，玩家通过聊天请求接取或推进；服务端检查实际位置、物品、知识和 NPC 在场状态。最终交付、NPC 实际余额/库存支付奖励与完成记录一次结算，每分支只领取一次。打开任务日志、查询、构建提示和迁移均不执行任务。

## 升级与回退

0.9.x → 0.10.0 不自动升级 v1/v2 世界、不改变旧模板哈希、不批量改写聊天。旧知识规则、单阶段、可选双阶段与正文重写保持。

1. 停止生成，整库备份并确认 `stDataDir`；保留旧版本和原资料。
2. 使用待复验候选提交及其锁文件，执行 `npm ci` 和 `./start.command`。
3. 模板编辑器中显式“启用任务规则（v3）”，配置 NPC 初始资金、任务阶段、条件、最终交付和来源奖励物品。初始物品在库存区配置。内部备注不进入玩家视图；可见任务名和目标不要提前写尚未揭示的秘密。
4. 用玩家/指定角色预览，再保存发布模板。新聊天使用该 v3 模板；旧聊天从“作者视图（含秘密）→ 更新模板”预览、备份并迁移全部候选/检查点/隐藏后续。任一坏恢复点阻断整份迁移，不给出部分结果。
5. 旧聊天升级从空任务进度开始，已有余额/库存/知识保持；初始 NPC 资金和初始知识只影响新聊天。新增任务不自动接取、推进或领奖。
6. 既有任务改定义、阶段、条件、交付、奖励、删除或改 ID 首版阻断迁移；新规则请创建新 ID。事实正文/公共属性的保守迁移限制继续生效。旧叙事包保持原来源，迁移后不匹配会禁用重写。

v3 不支持降级到 v2/v1。回退到 0.9.x 前停止服务，保存当前资料，恢复升级/迁移前独立备份，再按旧锁文件安装和构建。不要删除字段强制回退。

## 验收与候选包

```sh
npm ci
npm run check
npm run build
npm run verify:quests
npm run verify:ci
npm run verify:browser
npm run verify:local
npm run release:pack
npm run verify:release -- /绝对路径/PiTavern-0.10.0.tar.gz
```

- 任务专项 65 组：结构/投影 6、纯规则/事务 11、三模式单/双阶段游戏 28、生命周期/迁移 10、边界 10。包含 1000 回合请求、超预算与最终 revision 冲突回滚。
- 完整离线 CI 27 套，Chromium 68 项；任务界面覆盖作者从 v2 启用 v3、配置/预览/发布、390px 和实际候选反转时日志即时刷新。
- Node 22/24 CI 必须对应最终候选准确提交。该提交重新打包，验证源码 SHA-256、全新安装、HTTP/WS、运行版本和端口回收；不复用旧版本候选包。
- `verify:local` 只在真实资料副本中解析、备份恢复及导入，前后逐文件 SHA-256 对比，保持原资料和本机配置。
- 本地模拟供应商验证请求内容和真实服务端结算。真实供应商、主动接取/推进、拒绝原因叙述与可玩性人工验收为 `not_requested`；不能据合成结果宣称质量或可玩性提升。

## 边界

- 只支持作者确定的线性任务；无随机、分叉、失败期限、循环、离线推进或 NPC 自主目标。
- 玩家默认接口、三种上下文模式、工具、叙事包和诊断使用过滤后的玩家视图。NPC 私人知识只用于服务端条件，不交给同一模型要求保密。
- v3 未选路线的正文预览、名称备注及搜索片段须先切换后查看。恢复 v2/v1/无世界时，历史任务与知识诊断仍按当前有效视角过滤；实际用量和原始活动文件不回退。
- 作者入口、JSONL 和备份携带完整秘密与任务定义；本地作者系统不是多人访问控制。MD 只导出当前活动路径正文。
- 普通角色卡、世界书、变量和已有正文中的秘密不自动识别或清洗。已显示的正文无法可靠收回，也不承诺阻止模型从公开线索推断。
