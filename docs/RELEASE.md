# 0.8.0 发布与升级

0.8.0 聚焦知识与秘密规则第一版。作者定义确定事实、初始知情和受控交互；玩家叙事模型只接收公共及已获知内容。NPC 私人知识仅供服务端规则判定，单阶段模型不会同时收到完整秘密。完整字段、限制和信息出口见 [WORLD_KNOWLEDGE.md](WORLD_KNOWLEDGE.md)。

发布流程：确认最终提交的 Node 22/24 CI，通过后从该提交重新生成源码包并执行 `verify:release`；公共标签与 GitHub Release 使用同一提交和包，不复用旧候选包。独立验收通过后再正式发布。

## 升级与回退

0.7.x → 0.8.0 不自动升级 v1 世界、不改变旧模板哈希，也不批量改写聊天。0.7 的上下文构建、预算与恢复语义保持。

1. 停止生成，整库备份并确认 `stDataDir`。
2. 切换到 0.8.0 提交，按锁文件安装并执行 `./start.command`。
3. 在模板编辑器中选择“启用知识规则（v2）”，编辑事实与秘密、初始知情角色、揭示交互。公共交互名称/ID 会发给模型，不能在其中填写秘密。用玩家和指定角色预览验证初始可见内容，再保存发布。
4. 新聊天选择该 v2 模板；旧聊天从世界状态的“作者视图（含秘密）→ 更新模板”预览并应用。应用前自动备份，原子迁移所有恢复点；初始知情只作用于新聊天，不授予旧分支。
5. 游戏世界窗口默认显示“已知线索”及来源。模型只能选择公共交互 ID，服务端检查规则后暂存知识；本轮后续请求可使用暂存事实，整轮失败/停止不落盘。
6. 修改既有事实正文、删除/改 ID、改变公共属性首版阻断；交互调整只影响未来执行，不撤销知识。新增公共事实会立即对所有路径可见。

v2 不支持降级成 v1。回退到 0.7.x 前停止服务，保留当前资料，恢复升级/迁移前的独立备份，再按旧锁文件重新安装与构建。旧程序不能安全执行 v2 世界；勿依靠删除字段回退。

```sh
npm ci
npm run check
npm run build
npm run verify:knowledge
npm run verify:ci
npm run verify:browser
npm run verify:local
npm run release:pack
npm run verify:release -- /绝对路径/PiTavern-0.8.0.tar.gz
```

- 知识专项 53 组：结构/视图 7、事务 7、出口 9、生命周期/迁移 7、本地合成游戏 23。三种模式截取完整供应商请求，包括工具结果和续请求，检查揭示前秘密正文、内部 ID 和作者备注均不存在，揭示后作者备注仍不发送。
- 恢复 v1 或未绑定世界的备份后，旧 v2 活动记录仍按当前有效视角过滤；实际交互/game_content 回归覆盖 HTTP/WS 与第二页活动，保留旧记录兼容、用量和本地原始文件。
- 验证暂存可叙述、失败/停止撤销、重复幂等、查询与规则越权拒绝、不同角色/分支/缓存隔离、候选/检查点/swipe/隐藏 continuation 恢复、JSONL 导入与重启、备份恢复再迁移、MD/JSONL 导出边界，以及原有金额/库存/移动与长局行为。
- CI 25 组、Chromium 63 项；界面新增 v1 显式启用 v2、事实/知情/交互编辑与保存发布、玩家/NPC 预览、默认接口过滤、独立作者入口、获知来源与 390px 布局。
- `verify:local` 默认只在真实资料副本上解析、备份恢复和导入，前后逐文件 SHA-256 对比；不调用供应商。原资料和本机配置保持不变。
- 真实供应商未调用，真实模型对角色知识的遵循需另列人工验收；合成测试只验证实际输入和服务端状态，不能替代模型质量评估。
- 最终提交须通过 Node 22/24 CI；源码包再次验证 SHA-256、纯源码、含空格目录全新安装、一键启动、HTTP/静态资源/WS、运行版本及端口回收。

## 边界

- 本地作者可查看完整资料，不是多人访问控制；作者视图、JSONL 和备份含全部秘密。分享脱敏存档需要独立契约，本版不提供。
- 普通角色卡、世界书、宏、变量、作者注释和已写入正文不会自动识别或清洗秘密。分支目录保留已有正文预览，但不会将未选路线送入当前模型历史或用作知识授权。
- 流式正文一经显示无法撤回，不保证消除模型从公共线索进行的推断。未实现误解、谎言、遗忘、关系变化、NPC 自主行动或双阶段生成。
- 长局规则摘录仍有数量/长度限制，不能保证所有自然语言线索被识别；真实大库和模型表现须按实际资料另行验收。
